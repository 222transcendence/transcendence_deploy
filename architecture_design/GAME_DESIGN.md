# Game Design — 산성비 (Acid Rain Typing Battle)

과제(ft_transcendence subject v20.0) 기준으로 "실시간으로 여러 유저가 동시에 상호작용하는 웹 게임"이면
`Gaming and user experience`(Major) · `Remote players`(Major) 요건을 충족한다.

## 1. 게임 개요

- **인원**: PvP는 2~4인 배틀로얄(`transcendence_deploy#91`/`transcendence_deploy#92`)이다. AI
  연습전은 사용자 1명 대 AI 1명의 1:1 전용 모드다. 전략형 단어 선택, 단어 상태 전이, 낙하/데미지
  원칙은 두 모드가 같은 엔진 판정으로 공유한다.
- **핵심 루프**: 서버가 단어를 생성해 참가자 전원에게 **동일한 단어 스트림**을 동시에 브로드캐스트한다.
  화면 위에는 여러 `ACTIVE` 단어가 동시에 떨어질 수 있으며, 플레이어는 짧고 안전한 단어와 길고 강한
  단어 중 어떤 단어를 먼저 지울지 선택한다.
- **전략성**: 짧은 단어는 성공하기 쉽지만 공격력이 낮고, 긴 단어는 입력 부담과 선점·시간초과 위험이 더
  크지만 공격력이 높다.
- **승패**: PvP는 마지막 생존자 승리(last-survivor-wins)이며, 180초 제한 시간까지 2명 이상 생존하면
  HP 기준으로 순위를 확정한다. AI 연습전은 상대 HP를 0으로 만들면 KO 승리하고, 시간 종료 시 HP가 더
  높은 쪽이 승리한다. 같은 이벤트 처리 결과 승자를 단독으로 정할 수 없으면 무승부다.
- **서버 권위**: 단어 스폰 시각/순서, 정오답 판정, 데미지 계산, 승패 판정은 전부 서버가 결정한다.
  클라이언트는 서버가 보낸 이벤트를 그리기만 하며, 클라이언트 로컬 타이머로 판정하지 않는다(레이턴시
  조작 방지).

## 2. State Machine

```
WAITING → COUNTDOWN → IN_PROGRESS → FINISHED
```

| Phase | 설명 | 트리거 |
|---|---|---|
| `WAITING` | 로비에서 두 플레이어가 방에 입장, `SET_READY`로 준비 완료 대기 | 로비 프로토콜(`WEBSOCKET_PROTOCOL.md` §0)에서 처리, `/game` 네임스페이스 진입 전 |
| `COUNTDOWN` | `match_ready` → `match_start`(동기화된 시작 시각) 사이의 짧은 카운트다운 | 양쪽 소켓이 `join_room` 완료 |
| `IN_PROGRESS` | 단어 스폰 루프 동작, HP 변동, 재접속 처리 | `match_start` 이후 |
| `FINISHED` | HP 0 도달 / 180초 경과 / 상대 퇴장(FORFEIT) | `match_end` 브로드캐스트, `MatchHistory` 저장 |

## 3. 핵심 메커닉 (MVP 확정 수치)

### 3.1 HP & 매치 종료
- 모든 참가자의 HP 초기값은 `100`.
- 이 게임은 틱 기반이 아니라 `word_cleared`/`word_missed` 이벤트가 발생하는 시점에만 HP가 바뀌는
  이벤트 기반 판정 구조다. HP 변화 이벤트 하나를 처리한 뒤 즉시 종료 조건을 확인한다.
- **PvP 탈락(2~4인)**: 특정 참가자의 `HP <= 0`이 되는 순간 즉시 탈락 처리한다. 탈락자는 관전 목적으로
  방에 남아 상태를 받을 수 있지만 더 이상 `word_submit` 판정 대상이 아니다. 탈락 시 서버는
  `player_eliminated` 이벤트를 브로드캐스트한다.
- **PvP KO(2~4인)**: 탈락 처리 결과 생존자가 1명만 남으면 즉시 매치 종료, 마지막 생존자가 승리한다
  (`match_end.reason = 'KO'`).
- **AI 연습전 KO(1:1)**: `word_cleared` 처리 결과 한쪽 HP만 `0`이 되면 다른 쪽이 승리한다.
- **동시 KO 무승부**: 같은 이벤트 처리 결과 승자를 단독으로 정할 수 없으면 무승부다(`winnerId = null`).
  1:1에서는 `word_missed`로 양쪽 HP가 동시에 `0`이 되는 경우가 대표적이다.
- **시간 종료**: 매치 상한 `180초`에 도달하면 남은 HP를 기준으로 결과를 확정한다. PvP는 전체 참가자의
  ranking을 확정하고, 최고 HP가 여러 명이면 공동 1위(무승부)로 처리한다. AI 연습전은 HP가 더 높은 쪽이
  승리하고, HP가 같으면 무승부다.
- **PvP rank 산정(2~4인)**: 탈락자의 rank는 탈락 순서의 역순으로 확정한다. 마지막 생존자는 1위다.
  TIME_LIMIT에서는 아직 생존 중인 참가자를 HP 내림차순으로 정렬해 남은 상위 순위를 확정하며, 기존
  동률/공동 우승 계약을 유지한다. 생존자는 탈락 시점에 고정된 HP/타수와 무관하게 항상 탈락자보다
  상위 순위를 가진다(backend#185). `match_end.ranking`에는 전체 참가자의 최종 순위를 포함한다.
- **FORFEIT**: 명시적 퇴장이나 연결 종료에 따른 몰수 처리는 기존 연결 종료 정책을 따른다. #76에서는
  재접속 유예 시간이나 새로운 종료 정책을 만들지 않는다.

### 3.2 단어 은행
- `src/game/acid-rain/word-bank.ts`에 정적 배열로 관리되는 **한국어 큐레이션 단어 300~500개**
  (현재 400개, `#73`).
- 각 단어는 `{ text, keystrokes }` 쌍으로 저장된다. `keystrokes`는 **음절 수가 아니라 2벌식
  키보드 기준 실제 타건 횟수**(`keystroke-count.ts`)다 — 쌍자음(ㄲㄸㅃㅆㅉ)·ㅒㅖ는 Shift 포함
  2타, 이중모음(ㅘㅙㅚㅝㅞㅟㅢ)·겹받침(ㄳㄵㄶㄺㄻㄼㄽㄾㄿㅀㅄ)은 두 키 조합 2타로 계산해서, 음절
  수가 같아도 실제 타이핑 시간이 다른 단어(예: "왜"(3타) vs "새"(2타))를 구분한다.
- `keystrokes`는 기본적으로 정적 하드코딩 값이다 — 계산 로직이 나중에 바뀌어도 이미 확정된
  단어들의 난이도가 조용히 변하지 않도록 하기 위함. 새 단어를 추가할 때는 `keystrokes: 0`으로
  두면 `countKeystrokes(text)`로 자동 계산돼 채워진다(값을 직접 계산할 필요 없음).
- **난이도 구간(버킷)**: 스폰 가중치·표시 등 상대적 난이도가 필요한 곳에서는 아래 구간을 쓴다.
  현재 단어 은행 분포 기준(400개)으로 각 구간이 고르게 나뉘도록 정함.

  | 구간 | keystrokes 범위 | 현재 단어 은행 내 개수 |
  |---|---|---|
  | LOW | 2~5 | 160개 |
  | MID | 6~9 | 184개 |
  | HIGH | 10 이상 | 56개 |

### 3.2b 낙하 위치·높이 동기화
두 클라이언트가 같은 단어를 "동일한 스트림"으로 인지하려면 가로 위치보다 **세로 낙하 진행도(높이)가
먼저 맞아야 한다**. 우선순위:

1. **높이(진행도) 동기화 — 우선순위 1.** 클라이언트는 단어 애니메이션 시작 시각을 로컬 수신 시각이
   아니라 서버 `word_spawn.spawnedAt`을 클록 오차 보정한 값으로 잡는다. 이렇게 하면 네트워크 지연이
   양쪽에서 달라도 같은 시각에 같은 높이로 보인다. 판정 자체는 서버 권위이므로 높이가 살짝 어긋나도
   결과에는 영향 없지만, 어긋난 채로 두면 "동일 스트림 브로드캐스트"라는 설계 원칙과 시각적으로
   맞지 않는다.
2. **가로 위치(레인) 동기화 — 우선순위 2.** 화면은 `LANE_COUNT = 5`개의 가로 레인(0~4)으로 나뉘고,
   서버가 스폰 시점에 레인을 배정해 `word_spawn.lane`으로 브로드캐스트한다(`#100`). 완전히 빈 레인이
   있으면 그중에서도 현재 사용 중인 레인과 바로 인접(±1)하지 않은 레인을 우선한다 — 블록이 커진
   단어(`#98`)끼리 옆 레인에서 동시에 떨어지며 겹쳐 보이는 것을 줄이기 위함. 인접하지 않은 빈 레인이
   없으면 아무 빈 레인이나, 빈 레인이 아예 없으면(활성 단어 수가 레인 수 이상, `#100`) 가장 적게
   점유된 레인을 골라 **한 레인에 여러 단어가 동시에 낙하할 수 있다**(레인당 1개라는 예전 가정 폐기).
   판정은 텍스트 기준이라 레인이 겹쳐도 게임 결과에는 영향 없는, 순수 시각적 일관성을 위한 보강.
3. 재접속 시 `state_sync`로 복구되는 진행 중 단어는 원래 배정된 레인과 낙하 진행도(spawnedAt 기준)를
   그대로 유지한다 — 새로 애니메이션을 시작하거나 위치를 재계산하지 않는다.

정본은 `WEBSOCKET_PROTOCOL.md` §6.3 "계약 확정 노트" 참고.

### 3.3 스폰 간격 (난이도 램프)
```
interval(ms) = max(700, 2000 - 50 * floor(elapsedSec / 10))
```
시작 2000ms에서 10초마다 50ms씩 빨라지며 700ms에서 바닥을 친다.

### 3.3b ACTIVE 단어 누적과 스폰 skip (`#76`, `#100`)
- 방 하나의 최대 동시 `ACTIVE` 단어 수는 참가자 수에 비례한다 — 인당 5개(`WORDS_PER_PLAYER`),
  즉 2인 매치는 10개, 3인은 15개, 4인은 20개까지 동시에 떨어질 수 있다(매치 시작 시 고정, 중간에
  참가자가 탈락해도 줄지 않음). 예전엔 인원수와 무관하게 항상 5개였다.
- 스폰 차례가 왔을 때 이미 이 상한만큼 `ACTIVE` 단어가 있으면 해당 스폰은 **skip**한다.
- skip은 숨은 난이도 보정이 아니다. skip된 차례를 나중에 몰아서 보충하거나 다음 스폰 간격을 늘리지
  않는다. 다음 스폰 차례는 기존 스폰 간격 공식에 따라 다시 계산된다.
- 동일 텍스트의 `ACTIVE` 단어가 동시에 존재하는 것은 금지한다. 이미 같은 `text`가 낙하 중이면 서버는
  다른 단어를 고르거나, 유효한 대체 단어를 고르지 못한 경우 해당 스폰을 skip한다.
- 이 제한은 입력 문자열과 `wordId`로 목표 단어를 고를 때 선택이 모호해지는 문제를 막기 위한 공통
  규칙이다.

### 3.4 난이도 구간 가중치 (경과 시간별, `#100`에서 페이스 조정)
| 경과 시간 | 출제 구간 |
|---|---|
| 0~10초 | LOW만 |
| 10~40초 | LOW + MID |
| 40초~ | LOW/MID/HIGH = 25/35/40 가중치 |

예전엔 90초가 지나야 HIGH가 25% 확률로만 나와서, 180초 매치의 절반이 지나야 어려운 단어를 거의
못 보는 문제가 있었다.

각 구간 내에서 실제 단어는 균등 랜덤으로 뽑는다. (구간 정의는 §3.2 표 참고. `#75`에서
`WORD_BANK.filter(w => w.keystrokes <= 5)` 같은 방식으로 구간별 서브셋을 캐싱해 사용할 것을
권장 — 매 스폰마다 필터링하지 않도록.)

### 3.5 낙하 시간
```
fallDurationMs = (4000 + 250 * keystrokes) * max(0.6, 1 - elapsedSec / 300)
```
단어의 타건 횟수(`keystrokes`)에 비례해 기본 시간을 주되, 경과 시간이 늘수록 전체적으로
빨라진다. (예: keystrokes=2 → 시작 시 4500ms, keystrokes=17 → 시작 시 8250ms)

#76의 공통 전략형 규칙에서는 긴 단어가 짧은 단어보다 더 많은 시간을 받는 원칙은 유지하되, 추가 시간은
입력 부담을 **일부만** 보정해야 한다. 긴 단어의 공격력이 높은 만큼 입력 중 오타, 상대에게 먼저 빼앗김,
다른 급한 단어를 놓치는 기회비용이 남아 있어야 "고위험·고보상"이 성립한다.

현재 공식은 긴 단어에 비교적 넉넉한 추가 시간을 주므로, 최종 구현 계수는 후속 밸런싱/플레이테스트에서
조정한다. #76에서는 "길이에 따른 추가 시간을 축소해 입력 부담을 완전히 상쇄하지 않는다"는 설계 원칙만
확정한다.

### 3.6 데미지
- **정타(단어를 먼저 지움)**: `5 + ceil(keystrokes / 2)` 데미지를 준다. 지워진 단어는 모든
  클라이언트에서 즉시 제거한다.
  - 1:1 PvP 및 AI 연습전: `clearedBy`의 유일한 상대가 피해를 받는다.
  - 2~4인 PvP: `clearedBy`를 제외한 생존 상대 중 서버가 무작위로 고른 1명이 피해를 받는다.
- **미스(단어가 바닥에 닿음)**: 현재 생존 참가자 전원에게 고정 `3` 데미지를 준다("산성비를 함께
  맞는다" 컨셉). 1:1에서는 결과적으로 양쪽 참가자가 피해를 받는다. 탈락자 처리와 탈락자를 포함한 전체
  참가자 HP 표시는 `WEBSOCKET_PROTOCOL.md`의 현재 2~4인 PvP 계약을 따른다.
- 대표 비교:

  | 구간 | 대표 타수 | 정타 데미지 | 현재 공식 기준 시작 낙하 시간 | 전략 의미 |
  |---|---:|---:|---:|---|
  | LOW | 4 | 7 | 5000ms | 성공하기 쉽지만 공격력이 낮음 |
  | MID | 8 | 9 | 6000ms | 보통 위험·보상 |
  | HIGH | 12 | 11 | 7000ms | 공격력은 높지만 입력 부담과 경합 위험이 큼 |
  | HIGH 상단 | 16 | 13 | 8000ms | 큰 공격 기회지만 실패 시 기회비용이 큼 |

### 3.7 목표 선택과 입력 처리 (`#76`)
- 참가자 수와 무관하게 별도 클릭 선택이나 target lock UI를 두지 않는다. 입력 문자열이 어떤 `ACTIVE` 단어의
  전체 `text`와 정확히 일치하는 순간, 클라이언트는 그 단어의 `wordId`로 `word_submit`을 보낸다.
- 부분 문자열은 판정하지 않는다. 클라이언트가 prefix 하이라이트를 표시할 수는 있지만, 서버 제출은 전체
  텍스트가 정확히 일치할 때만 발생한다.
- 입력 도중 목표 변경은 허용한다. 플레이어가 입력창을 지우거나 다른 문자열을 입력하면 다른 단어를
  노릴 수 있다.
- 제출 가능한 단어를 찾아 `word_submit`을 보낸 뒤에는 입력창을 즉시 비운다. 서버가 제출을 거절하더라도
  이전 입력을 자동 복구하지 않는다.
- 다른 플레이어가 먼저 지운 단어를 내가 입력 중이었다면, 서버의 `word_cleared` 이벤트에 따라 그 단어는
  즉시 화면에서 제거된다. 입력창은 자동으로 지우지 않으며, 플레이어가 남은 입력을 지우거나 다른 단어로
  이어서 전환할 수 있다.

### 3.8 단어 상태 전이와 경합 처리 (`#76`)
- 낙하 중인 단어의 상태는 `ACTIVE`다.
- 해결된 단어는 `CLEARED` 또는 `MISSED` 중 하나의 최종 상태만 가질 수 있다.
- `CLEARED`: 서버가 유효한 `word_submit`을 먼저 처리해 단어를 제거한 상태.
- `MISSED`: 서버가 단어의 바닥 도달을 먼저 처리해 단어를 제거한 상태.
- `CLEARED`와 `MISSED`가 경합하면 서버에서 먼저 처리된 단일 상태 전이만 유효하다. 이후 같은 단어에
  대한 제출은 거절한다. 구체적인 오류 코드명은 `transcendence_backend#109`의 WebSocket 계약 정렬에서
  확정한다.
- 같은 단어가 이미 해결된 뒤 뒤늦게 도착한 제출은 HP를 다시 변경하지 않는다.

### 3.9 재접속
연결 종료와 `FORFEIT` 처리는 기존 WebSocket/게임 연결 종료 정책을 따른다. #76에서는 재접속 유예 시간,
일시정지, 새로운 종료 정책을 추가로 정의하지 않는다.

### 3.10 매치 종료 시 저장
매치 종료 기록은 기존 PvP/AI 저장 정책을 따른다. DB/history 구조 변경과 참가자 조인 테이블 구현 세부는
별도 구현 이슈에서 다룬다.

## 4. WebSocket 이벤트 스키마

전체 이벤트 정의(payload 상세)는 `WEBSOCKET_PROTOCOL.md` §6을 정본으로 한다. 이 문서는 게임 규칙만
다루고, 프로토콜 세부사항은 중복 기술하지 않는다.

## 5. 직업/클래스 시스템 없음

산성비 대전은 별도 직업이나 클래스 선택 없이 닉네임만으로 진행된다.

## 6. 향후 확장 여지 (과제 모듈 매핑)

- **AI 모듈(Major)**: AI가 사람 대신 단어를 입력하는 상대로 구현 가능 — 반응 지연에 랜덤성을 부여해
  "완벽하지 않은" 사람다운 플레이를 시뮬레이션. AI 연습전은 사용자 1명 대 AI 1명의 1:1 전용 모드로
  별개로 진행한다(`transcendence_backend#99`).
- **Multiplayer game (3인 이상, Major)**: PvP는 `transcendence_deploy#91`/
  `transcendence_deploy#92`의 2~4인 배틀로얄 계약을 현재 범위로 유지한다. #76의 전략형 단어 규칙은
  참가자 수와 무관하게 이 PvP 범위에도 적용된다.
- **Tournament(Minor)**: 매치 자체가 짧고(최대 180초) 승패가 명확해 토너먼트 브래킷에 적합.
- **Game customization(Minor)**: 난이도 파라미터(스폰 간격, HP, 데미지 배율)를 방 생성 시 옵션화 가능.
