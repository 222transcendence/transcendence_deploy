# Database Schema Design

## 1. Entities & Relationships

### User
- `id`: Primary Key (UUID, autogenerated)
- `email`: String (Unique)
- `nickname`: String (Unique)
- `password`: String (Hashed, Nullable for OAuth users)
- `avatar`: String (Default avatar path)
- `status`: Enum (ONLINE / OFFLINE / IN_GAME)
- `wins`: Integer (Default 0)
- `losses`: Integer (Default 0)
- `createdAt`: Timestamp
- `updatedAt`: Timestamp

### Character
- `id`: Primary Key
- `name`: (e.g., "Magician")
- `base_hp`: Integer
- `base_atk`: Integer
- `base_def`: Integer
- `skills`: JSON (Skill triggers and effects)

### Card (Action Card)
- `id`: Primary Key
- `type`: (MOVE, ATK_SWORD, ATK_GUN, DEF, SPECIAL)
- `value_top`: Integer
- `value_bottom`: Integer

### MatchHistory
- `id`: Primary Key
- `host_user`: FK to User
- `guest_user`: FK to User
- `winner`: FK to User
- `turns_played`: Integer
- `match_data`: JSON (Log of all actions for replay)

## 2. Real-time Session State (Stored in Redis)
실시간 대전 중인 방의 상태는 고속 처리를 위해 Redis에 임시 보관함.
- `room_id`: {
    "phase": "MOVE",
    "host_cards_submitted": [...],
    "guest_cards_submitted": [...],
    "distance": 3,
    "current_turn": 5
  }

### Friend
- `id`: Primary Key (UUID, autogenerated)
- `requesterId`: FK to User(id)
- `receiverId`: FK to User(id)
- `status`: Enum (`PENDING` / `ACCEPTED`)
- `createdAt`: Timestamp
- `updatedAt`: Timestamp

#### Friend Relationship Rules
- 친구 관계는 단방향 1 row로 저장함.
- 친구 목록 조회 시 requester/receiver 양방향을 모두 조회함.
- 중복 요청 검사는 양방향으로 수행함 (A->B가 있으면 B->A도 차단).
- `ACCEPTED` 관계가 이미 있으면 새 요청은 `409 Conflict`.
- 친구 요청 거절은 별도 상태를 만들지 않고 `PENDING` row 삭제 방식으로 처리함.
- 온라인 상태는 User 엔티티의 `status` 필드를 그대로 사용함.
- Redis/WebSocket/session 기반 실시간 온라인 상태 관리는 본 이슈 범위에서 제외함.
